# 定期実行の設定（週刊 不動産ニュース）

毎週木曜の朝に記事を自動生成するための Routine（スケジュール実行）の設定内容です。

## スケジュール

| 項目 | 値 |
|---|---|
| Routine 名 | 週刊 不動産ニュース（毎週木曜 朝6時 JST） |
| トリガー ID | `trig_01WoP4CHMbsBCANK3ADdfSnc`（2026-08-19 登録） |
| 実行タイミング | 毎週木曜 06:03（JST） |
| cron（UTC） | `3 21 * * 3` ← 水曜21:03 UTC = 木曜06:03 JST |
| 実行モード | 毎回新しいセッションを起動（`create_new_session_on_fire: true`） |
| 実行環境 | `env_017eoecLsN4sa5jZJyXcyuDa` |
| 完了通知 | プッシュ通知・メール ともに ON |

> 分を `:03` にしているのは、世界中のスケジュール実行が毎時ちょうどに集中するのを避けるためです。きっかり6:00にしたい場合は `0 21 * * 3` に変更してください。

> cron は **UTC で評価される**ため、JST 木曜6時は「水曜21時 UTC」になります。曜日が1日ずれる点に注意してください（`* * 4` と書くと木曜21時 UTC＝金曜6時 JST になってしまいます）。

## 実行時に渡すプロンプト

```
今週分の「週刊 不動産ニュース」記事を作成してください。リポジトリは yotsuba-ai/mortgage-simulator です。

## 手順

1. まず `news/README.md` を読み、情報ソース一覧・記事フォーマット・執筆ルールを確認する。直近号（`news/` 内の最新の `YYYY-MM-DD.md`）も読み、内容の重複を避ける。前号と同じ数値をそのまま繰り返さず、その後に新しく公表されたデータを優先する。

2. 情報収集する。**この環境は外部サイトへの直接アクセス（WebFetch / curl）がネットワークポリシーでブロックされているため、必ず WebSearch を使うこと。** WebFetch は egress 403 で失敗するので試さない。`allowed_domains` でソースを絞った検索を複数回投げる。最低限カバーするテーマ:
   - その週に新しく公表された統計・ニュース（これを「今週の一番」として冒頭に置く）
   - 新築分譲マンション市場動向（不動産経済研究所）
   - 中古マンションの成約価格・成約件数（レインズ、アットホーム）
   - 新築戸建価格・募集家賃動向（アットホーム）
   - 住宅市場・購入者動向（SUUMOジャーナル）
   - 投資用不動産の市況・融資動向（楽待新聞）
   - 住宅ローン金利と日銀の金融政策
   - 地価（公示地価・基準地価・路線価）、制度・法改正、業界動向

3. `news/README.md` の記事フォーマットに従って `news/YYYY-MM-DD.md`（日付は当日＝木曜日）を作成する。「今週の3行まとめ」→「本編6〜8本（各項目に数値の表と『読みどころ』）」→「来週以降のウォッチポイント」→「情報ソース」の構成。単なる要約で終わらせず、数字の裏側にある意味を解説する「読みどころ」を必ず入れる。

   **当日付のファイルが既に存在する場合でも、処理をスキップせずに内容を更新すること。** 前回の収集日以降に公表された情報を反映し、より重要な材料が出ていれば「今週の一番」を差し替える。冒頭の「データ収集日」は必ず当日に更新する。

4. 執筆ルールを守る: 数値には必ず時点を添える／「首都圏」「東京都」「都心3区」など集計範囲を混同しない／推測と事実を区別し、解釈はそうと分かる書き方にする／一次資料が確認できなかった数値はその旨を注記する／住宅ローン金利の話題では `../index.html` の住宅ローンシミュレーターへの導線を入れる。

5. `news/README.md` のバックナンバー表に今週号の行を追加する。

6. ブランチ `claude/weekly-real-estate-news-wbiosc` にコミットして `git push -u origin claude/weekly-real-estate-news-wbiosc` する。ブランチが存在しない場合、または既存の PR がマージ済みの場合は、`git fetch origin main && git checkout -B claude/weekly-real-estate-news-wbiosc origin/main` で main から作り直してから push する（その場合は force-with-lease 可）。**PR は明示的に依頼されない限り作成しないこと。**

7. 最後に `SendUserFile` で作成した記事ファイルをユーザーに送り、3行まとめを添えて日本語で報告する。
```

## 登録方法

新しいセッションで次のように依頼すれば登録されます。

> `news/ROUTINE.md` の内容で Routine を登録して

## 発火しなかった場合の確認手順

### 2026-08-20 の未発火インシデント

初回の予定実行（2026-08-20 06:03 JST）で **記事の生成・push・通知のいずれも発生しませんでした**。確認できた事実は次のとおりです。

- 登録自体は成功（API 応答で `enabled: true`、`next_run_at: 2026-08-19T21:03:00Z`）
- cron `3 21 * * 3` の曜日変換は正しい（2026-08-19 は水曜 → 木曜 06:03 JST）
- 予定時刻の約4時間後まで、どのブランチにも新規コミットなし
- プッシュ通知・メールともに未着 → **実行が完了に到達していない**（起動していないか、起動直後に落ちたか）
- 記事生成のパイプライン自体は正常。同日に本ドキュメントのプロンプトを手動実行したところ、情報収集から push・ファイル送付まで完走した（コミット `d30de2d`）

つまり **プロンプトや実行環境ではなく、Routine の発火機構側の問題** に切り分けられています。

### 確認する項目

1. **Routine が有効か** — `enabled` が false になっていないか。`ended_reason`（恒久的な無効化の理由）や `suspension_reason`（サブスクリプション停止など、一時的な保留）が付いていないか。どちらも空なら手動での一時停止
2. **実行環境が生きているか** — `env_017eoecLsN4sa5jZJyXcyuDa` が削除・停止されていないか。fresh-session 型の Routine は、この環境が使えないと起動に失敗する
3. **実行履歴** — 予定時刻に対応する実行記録があるか。あればエラー内容を確認する

### 確認方法

**claude.ai の Routines 画面**から確認するのが確実です。上記のトリガー ID で該当の Routine を開き、有効状態と実行履歴を見ます。

セッション内から確認する場合は claude-code-remote MCP サーバーのツール（`list_triggers` / `fire_trigger` / `update_trigger`）を使いますが、**このサーバーのツールは承認待ちで弾かれることがあります**。その場合は `/permissions` でサーバー名を許可リストに追加してください。サーバー名はセッションによって変わることがあるため、その時点の実際の名前を確認してから追加します。

### 復旧のしかた

- 一時停止されているだけなら、画面から有効化する
- 実行環境が失われている場合は、生きている環境で Routine を登録し直す（cron・プロンプト・通知設定は本ドキュメントのとおり）
- 復旧後は `fire_trigger` で手動発火し、実際に完走することを確認してから次の定期実行を待つ

## 既知の制約

- **Routine にコネクタが紐づいていない**：登録時、呼び出し元セッションが渡せるコネクタ権限を持っていなかったため、この Routine が起動するセッションでは MCP コネクタ（Google Drive など）のツールが使えません。記事作成に必要なのは WebSearch と git だけなので実害はありませんが、コネクタを使わせたい場合はコネクタを持つセッションから登録し直すか、claude.ai の Routines 画面で設定してください。
- **外部サイトへの直接アクセスがブロックされている**：この環境のネットワークポリシーにより、`athome.co.jp` / `suumo.jp` / `rakumachi.jp` / `mlit.go.jp` などへの WebFetch・curl は egress 403 で失敗します。記事の数値はウェブ検索経由で取得した各社の公表値であり、各サイトのページを直接読んでの裏取りはできていません。
- 各サイトを直接読ませたい場合は、環境のネットワーク設定で対象ドメインを許可リストに追加してください（[Claude Code on the web のドキュメント](https://code.claude.com/docs/en/claude-code-on-the-web)）。
